# LivingFin：图原生股票研报研究原型

当前已在线验证**巨潮公告按需发现**和**SearchCans/Bing 候选网页检索**，完整研报生成尚未恢复。先前的 `livingfin/pipeline.py` 是已停用的原型：它要求手工来源清单、预先批量取财务数据，且只读取 PDF 文本。它产生的 `runs/` 文件不可作为实验或研报结果。当前实现范围与后续工作见下文。

## 已可验证的来源发现

`CninfoDiscovery` 查询巨潮资讯网的公司公告接口。输入是具体证券代码、时间窗口，以及从研究问题产生的类别/关键词；输出是原始披露 PDF 的地址、标题、日期和查询覆盖情况。返回地址只代表**找到候选原件**，不是已经核实其中的事实。

```bash
python -m livingfin \
  --ticker 688825.SH \
  --start-date 2026-08-01 \
  --as-of 2026-09-22 \
  --category half_year_report
```

可选 `--keyword` 和 `--max-pages`。若结果分页被截断，输出 `truncated: true`，不能宣称检索穷尽。该公开网站接口不是已承诺稳定的商业 API；结构变化或访问限制必须显式报错，不能静默切到另一个来源。

## 待解决的核心能力

- 把“提出问题 → 选择财务/公告/开放检索工具 → 获取并核查证据 → 更新图 → 检查新问题”接成真正的运行循环，而不是一次性灌入所有材料。
- 复曜结构化数值需要保留请求、报告期、披露时间和口径，并明确其第三方数据身份；重要数值应对照原始披露。图表里独有、无法可靠核查的数值暂不入图。
- SearchCans/Bing 已能返回候选网页，但搜索摘要不是证据；仍需打开原网页、核查发布时间与内容。巨潮公告接口只覆盖公司披露，不能承担行业和外部事件搜索。检索或来源核查失败时，相关研究问题必须保留为缺口。
- 在上述获取与核验链成立后，才重新验证“相同证据下图约束写作 vs 证据自由写作”的唯一研究对照。
