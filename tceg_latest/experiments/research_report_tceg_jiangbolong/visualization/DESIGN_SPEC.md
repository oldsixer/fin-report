# TCEG 证据图谱可视化设计说明

## 设计目标

这不是一张为了展示节点数量而制作的“知识图谱海报”，而是一套面向金融研究者的证据审计工作台。核心任务是让研究者在同一个视野里完成三件事：理解研报的主要判断如何由数据和事件支撑；确认每一个事实或数字能否回到原始 PDF 的具体页和原文；识别当前图状态中仍然缺失、只可人工复核或论证链不完整的部分。因此界面固定保留三类对象：原始报告、图结构、节点/证据详情。图是主状态，PDF 是证据载体，详情面板是两者之间的解释层。

## 信息架构与交互

顶部只放报告身份、图状态哈希以及 4 个可审计的关键数字：854 节点、2509 条边、验证 0 错误、核心清单 63/63。主工作区分为报告、图、审计详情三栏。默认“核心论证”模式只展示核心主张及其一至两跳论据，避免 854 个节点同时出现造成不可读；“关键数据”模式优先展示手工核心清单命中的数字及其指标、期间、主体；“完整图”模式才加载所有节点，并在选中节点后突出邻居和相关边。搜索同时覆盖节点标签、节点 ID、证据片段与原始 source object。选择节点后，详情栏展示结构化字段、基准命中、警告和证据；点击证据即切换左侧报告页，并在页面图像下显示该 source object 的完整文本。因为 PDF 文本层没有稳定的像素坐标，本版不伪造页面框选位置，而使用页码跳转加逐字证据片段来保持真实性。

## 三个视觉方向

方向一“研究工作台”采用米白纸张、深墨文字和砖红强调，来源于杂志编辑长文与断言—证据的信息设计。它让报告页与研究图谱看起来像一套严谨的案头材料，适合作为默认版本。方向二“论证星图”采用温暖炭黑、琥珀与青灰，图区域占据最大视觉权重，关系线和选中路径更具空间感，适合演示整体论证网络，但仍避免常见的蓝紫霓虹界面。方向三“证据账本”采用瑞士机构网格、纯白底、黑色细线与信号红，将状态、编号、来源和告警设计成审计账目，最适合逐项验收和截图进入论文或技术文档。三个方向使用相同真实数据和相同交互，不以虚构指标、占位图表或装饰性卡片制造完成感。

## 视觉编码

Claim 使用砖红/珊瑚，DataPoint 使用蓝色，Event 使用琥珀，ReasoningStep 使用紫灰，Entity 使用青绿，Metric 与 Period 使用中性灰。边的颜色由关系语义决定：SUPPORTS 与 HAS_DATA 为积极支撑色，CAUSES 为橙色，DEPENDS_ON 为紫色，PREMISE_OF/CONCLUDES 构成论证链，结构性边在未选中时弱化。显式关系用实线，推断关系用虚线。带验证告警的节点显示警示环，命中人工核心清单的对象显示“CORE”标记。所有数字采用等宽或 tabular 字形；长证据文本保持可选择、可复制，不放进 SVG 路径。

## 边界与诚实性

验证状态“PASS”只说明 schema、ID、证据引用、DAG 和已实现的语义约束通过；6 个 warnings 必须在界面中原样呈现。核心清单 63/63 是 19 个语义项、34 个数据项和 10 个关系项的人工清单命中总和，不等于模型在全部可能事实上的真实精确率与召回率。56 个 source object 中 4 个 OPAQUE 代表图表图片无法从文本层解析，界面要允许按状态筛查这些对象。当前样本只是一份江波龙报告，不应以“通用”或“已经覆盖所有财报”描述它。

## 响应式与可访问性

桌面端以 1440×900 和 1920×1080 为主要验收尺寸。较窄屏幕下三栏改为可滚动的纵向区域，图区域保留最小高度。交互元素使用原生 button/input，键盘可聚焦；颜色之外同时用节点形状、文字标签和虚实线区分类型；正文对比度保持可读。页面不依赖远程字体、CDN 或网络请求，直接从本地文件打开即可工作。
