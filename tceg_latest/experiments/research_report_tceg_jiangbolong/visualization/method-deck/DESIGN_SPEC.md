# 从券商研报到 TCEG：HTML 方法 Deck 设计说明

## 目标与受众

这套 Deck 用来解释当前项目如何把一份券商研报转化为可审计的 TCEG 图状态。主要受众是论文审稿人、研究合作者和工程实现者，他们需要同时理解研究命题、系统结构、模型与确定性程序的分工、证据约束、关系验证和实验边界。演示不能停留在“用了大模型抽取”的抽象描述，而要让观众看到每一个阶段的输入、输出、失败处理以及真实规模。核心论点是：研报语言只是当前状态的一种呈现，具有稳定 ID、证据锚点和推导路径的图才是后续持续研究的主要语义状态。

## 输出格式与视觉系统

输出采用多文件 HTML Deck，固定画布 1920×1080；`index.html` 提供 3D 概览墙、键盘翻页、全屏演示和页码。视觉方向采用用户指定的 B 模板：参考 Stanford HAI AI Index 一类的学术研究报告语言。背景以暖白和纯白为主，深墨灰用于正文，Cardinal 红用于结论和关键路径，克制的蓝绿色用于数据与证据；不使用紫色渐变、装饰性 emoji、无意义卡片或虚构 KPI。标题使用结论式完整句，正文使用清晰的中文无衬线，必要时以 Georgia 类衬线提供学术出版气质。所有可见正文不小于 24px，页面坚持一页一个主观点和一个主要视觉对象。

## 内容结构

完整 Deck 共 12 页：封面；图是主状态的核心命题与语义契约；三页 Schema 字段词典，分别解释根状态与来源、节点与嵌套记录、关系与运行审计；端到端流程；来源保真层及抽取视图；LLM 与确定性解析的混合抽取；七类当前节点及数字尺度模型；证据门；关系提议、独立复核和 ReasoningStep 论证路径；最终图规模、结构验证、负向测试与人工核心清单。报告页和现有图谱前端截图属于内容必需的真实资产，用于证明输入和输出均为真实对象；流程图、节点统计和关系统计用 HTML/CSS 根据本地数据绘制。

## 叙事节奏

前 2 页回答“为什么做”；第 3–5 页先建立完整 Schema 心智模型；第 6–11 页解释“如何抽取与验证”；第 12 页展示当前可复现图状态。页面在大图、字段词典、流程、数据图和代码式结构之间切换。原始 PDF 与图谱截图只在需要证明来源和结果的页面使用，其他页面让结构本身成为视觉主角。

## 真实性与边界

Deck 中的所有字段、规模、比例、模型名、状态和测试结果必须能回到正式 JSON Schema、当前 `tceg.json` 或验证器。Schema 页必须覆盖根字段、Document、SourceObject、所有节点字段、所有边字段和边类型，以及 evidence、value、verification、extraction_run、coverage_manifest 与 rejected_candidates 的作用。当前候选输入来自 Luna 审计文件，管线同时支持 OpenAI-compatible API 分块抽取；不能把当前运行描述成纯 Python 或纯大模型。关系复核使用独立模型，置信度必须由模型直接输出 0–1 JSON number，不做 high/medium/low 的人为映射。

## 参考方向

现实参照为 Stanford HAI 的 AI Index Report：以严谨验证、广泛来源和面向研究者/决策者的数据表达为设计锚点。该参照仅用于视觉与叙事方法迁移，Deck 内容完全来自 LivingFin 当前项目。
